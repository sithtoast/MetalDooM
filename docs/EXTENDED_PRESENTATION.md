# Bundled sky, lighting and presentation — 0.10.0 build 164

This completes the native adapters that earlier milestones listed separately
from ordinary sky transfers, indexed lighting and extras resource loading. It is
still the bounded single-player preview: campaign playthrough/performance and
whole-frame software-renderer parity have separate acceptance requirements.

## Skies

The worker copies every level sky's type, both texture mappings and the actual
procedural fire columns generated by pinned Woof. The app never advances fire RNG.
Normal and fire backgrounds share the native sky projection; a foreground has
independent horizontal/vertical scroll, midpoint and scale. Palette index zero is
transparent in the foreground. Both layers follow texture animation translations. Transfers retain their side offsets/orientation;
stable sky IDs keep changing scroll values out of texture cache keys. Fire pixels
update an existing Metal texture once per presented tic. Global camera colormaps
also affect sky color. Optional software sky stretching and exact fixed-point
rasterization are not reproduced.

Saves now include each layer's current/previous scroll coordinates, fire intensity
buffer and update counter. Restore reconstructs visible fire columns without a
tic or RNG advance. Copying presentation is read-only. Engine fingerprints keep
older private saves from being opened with a different worker build.

## Brightmaps and tints

The worker resolves BRGHTMPS masks for textures, flats, sprite types and states.
State masks precede sprite masks; weapons use state masks. A marked source palette
index uses row zero unless a fixed map is active. Fullbright obeys the same fixed
map precedence. The selected custom colormap applies to both ordinary and bright
rows before normal/additive/custom translucency.

Tint selection follows the pinned renderer: side tint overrides sector tint;
plane tint overrides the light-transfer sector/own sector; thing tint overrides
its floor-light-transfer sector/own sector. Missing local tints inherit the
player's explicit sector colormap or the height-control sector's bottom/mid/top
map according to eye height. Shader vertices carry byte offsets into the copied
bank; references and fixed rows within each map are bounded before GPU access. HUD pixels remain unshaded.

## HUD and carousel

The effective SBARDEF in the ordered WAD stack is parsed as a bounded tree.
Supported bundled nodes are canvas, graphic, face, facebackground, number and
percent, with nested children, alignments, patch origins, number-font widths and
single-player weapon/slot/ammo/key/armor/feature/session conditions. The authored
status bar or fullscreen HUD is selectable; native minimal HUD remains available.
The multiplayer-only face background is inactive in these single-player plans.
The portrait retains native health/idle presentation; exact KEX portrait timing
is not claimed.

The unused extended fuel identifier in id24res's support HUD resolves to zero
when there is no independent ammo entry, as in the pinned Woof numeric resolver.
Rust's effective replacement HUD uses its actual native fuel/ammo slot. This
presentation adapter does not add a separate generic ID24 ammo inventory.

Weapon changes briefly display owned SM* icons, using selected/unselected artwork
and Rust's incinerator/calamity replacements where that profile uses them. The
native picker and menus remain the frontend. Arbitrary SBARDEF animation,
translation and tranmap extensions outside these bundled trees reject rather
than silently suggesting full support.

## Recorded music

When selected, a D_ track uses the corresponding H_ Ogg Vorbis lump if available.
Repeated-track aliases match effective MIDI bytes, so Doom II's D_STLKS2 finds
H_STALKS. Missing recorded variants use the existing MIDI path; the user may
explicitly select original MIDI. Selection, mute, pause and loop behavior share
the native music controls. No external decoder installation is required.

Vendor/stb contains the unmodified, SHA-256-pinned stb_vorbis source and MIT license.
The C adapter validates complete Ogg page framing/end-of-stream, limits input to
64 MiB, mono/stereo output, 8–192 kHz, 30 minutes and 256 MiB decoded PCM. It returns
an owned PCM copy; Swift wraps it as WAV for AVAudioPlayer. Malformed input rejects
before replacing the active player. App bundles include the decoder license.

## Private wire changes

The worker's ABI2 and eighteen exports remain. MVW5 framing is unchanged.

- **MGE6** keeps the 120-byte header. Sides grow36→40 bytes with tint ID at36;
  sectors grow140→152 with general/floor/ceiling tint IDs at140/144/148. Other
  strides and earlier offsets stay unchanged. Swift still decodes MGE5 fixtures.
- **MSP6** keeps the 32-byte header. Actor stride56→64 and weapon stride24→32;
  each appends tint ID and brightmap ID. Swift retains MSP5 fixture decoding.
- **MMT2** keeps MMT1's header and translation records, then a sky count. Each
  sky has type(4), background/foreground mappings(28 each), fire width/height(8),
  then width×height indexed fire pixels. A mapping has name(8), angle, midpoint,
  scales and global tint ID(4 each). Unused foreground records/dimensions are zero.
- **MBL4** keeps MBL3's 24-byte header and original palette/map/blend sections.
  It appends custom-map/mask/material-binding counts, 8704-byte custom maps,
  256-byte masks (ID0 is empty), then16-byte name/namespace/mask bindings.
  The native GPU bank uses34 rows per colormap, followed by masks. At most256 maps
  and512 masks are accepted. Existing MBL3 fixture decoding remains available.
- **MUI4** retains144 bytes; offset88 now carries armor class0–2. MUI3 fixtures
  with a zero reserved field still decode.
